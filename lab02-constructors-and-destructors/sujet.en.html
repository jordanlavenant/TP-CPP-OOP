# Context In lab 1, the SVG file was written by three free functions taking a stream, and in its last question the call to `svg::close` was removed: the browser refused the file with the message `Premature end of data in tag svg`. None of the three signatures required `open` and `close` to be matched, so the missing call went undetected at compile time. Here a constructor writes the header and a destructor writes the closing tag. **The closing tag is therefore written when the scope ends, and no call in the code produces it.** By the end of the session the program produces `tree.svg`, which holds a recursive tree of 2047 branches, each drawn in its own coordinate system and placed inside a nested group. # Objectives * Define a type whose constructor and destructor each write to the stream, not merely set and release members. * Understand why a reference member can only be initialized in the member initializer list. * Understand the order in which members are constructed and the reason for it. * Derive balanced tags from scope alone, where lab 1 could only maintain them by hand. * Observe which destructors still run when an exception unwinds the stack. # Requirements * The project must compile with `-Wall -Wextra` without a **single warning**. * All the checks in `tests/` must pass, including the check for the exception. * `build/tree.svg` must show the tree, and `build/broken.svg` must open without error. * Once the drawing is finished, the printed number of groups still open must be zero. # Files Four of the C++ files are complete as supplied, `include/canvas.hpp` among them; the other three have code left to write. * `include/color.hpp` and `src/color.cpp` define `color` in full; nothing is to be written in either. * `include/geometry.hpp` defines `point` and its free functions; nothing is to be written there. * `include/canvas.hpp` declares `canvas`: its constructors, its destructor, `line`, `open_group` and `close_group`. * The members of `canvas` are `out_` (the borrowed stream), `width_`, `height_` and `centre_`. * It also holds the counters `strokes_` and `depth_`. * The accessors `width`, `height`, `centre`, `strokes` and `depth` are declared there too. * So is `alive`, the accessor for the static counter `alive_`. * `include/canvas.hpp` also declares `group`, whose constructor opens a group of the drawing. * `src/canvas.cpp` contains the function bodies to write, each marked `TO WRITE`.
**A `canvas` is built from a `std::ostream&`, not from a file name.** The tests can therefore write to a `std::ostringstream` and read back what they wrote, without touching the disk. The stream does not belong to the `canvas`.
* `src/main.cpp` holds the recursive code that draws the tree with SVG transforms. * Its `branch` function draws one upward stroke at the origin, then calls itself for two smaller branches. * Its `draw_tree` function calls `branch`; the lines that place the tree are left for part 3. * `src/main.cpp` also defines `fragile`, a variant of `branch` that throws after 400 strokes. * `tests/test_canvas.cpp` contains the checks that are already provided; add the new ones there. The project builds with `cmake -S . -B build`, then `cmake --build build`. The executable is `build/output`. The command `ctest --test-dir build` runs the checks, and `build/output` writes the drawings to `build/tree.svg` and `build/broken.svg`. # Part 1
