# Context The canvas from lab 2 can only draw a line. Here one method is added, `draw`, which takes a shape by reference to the base and asks it for its SVG element. That is everything **the canvas will ever know about shapes**. Three concrete shapes are to be written: a circle, a square and an equilateral triangle. By the end of the session the program writes `garden.svg`: 520 shapes placed on a sunflower spiral, the three kinds intermixed, each scaled to an area set by its distance from the center alone.
**`scale_to_area`** is the function the lab is about: three lines long, not virtual, written once in the base. It works for a circle, for a square and for a triangle, because the two functions it calls, `area` and `scale`, are virtual.
# Objectives * Write the member functions of three classes derived from an abstract base. * Explain why the compiler rejects any object of a class that has a pure virtual function. * Write a non-virtual function in the base whose only access to the derived object is through virtual calls. * Understand what `override` makes the compiler check, and what happens when it is missing. * Destroy a shape through a pointer to a `shape` whose destructor is not virtual, and note the effect. # Requirements * The project builds with `-Wall -Wextra` and the compiler emits **zero warnings**. * The checks in `tests/` pass, including the one written in question 2.1. * `build/garden.svg` shows the 520 shapes, with no kind systematically larger than the others. * The program reports no **shape alive** after the garden is emptied. * Nothing is reported under `-fsanitize=address`. # Files Three files have code to write; everything else is supplied complete. * `include/color.hpp`, `src/color.cpp` and `include/geometry.hpp` provide `color` and `point`, written in lab 1. * `translated`, in `include/geometry.hpp`, returns a point shifted along x and along y. * `include/canvas.hpp` and `src/canvas.cpp` provide the `canvas` of lab 2, with a `draw` method added for this lab. * `include/shape.hpp` declares the base `shape` and the three derived classes `circle`, `square` and `triangle`. * `shape` declares four pure virtual functions: `area`, `perimeter`, `scale` and `outline`. * `shape` also declares a virtual `title` with a body and a non-virtual `scale_to_area`. * `circle` holds its radius in `radius_`, and `square` and `triangle` hold their side in `side_`. * `shape` holds the center in `centre_`, a `point`, which the three derived classes inherit. * `src/shape.cpp` holds the bodies to write, marked `TO WRITE`. * `src/main.cpp` holds the loop meant to fill `garden` with 520 shapes, and fills `trio` with one of each kind. * `make_shape`, supplied, returns the shape of rank `i` placed at a point. * The loop computes `distance` and `angle` for each shape, around the point `centre`. * Part 2 asks for the body of that loop and for the printing of `trio`. * `tests/test_shape.cpp` holds the checks already written and is where the new ones belong. The executable is `build/output` and the drawing is written to `build/garden.svg`. Build the project with `cmake -S . -B build` and then `cmake --build build`; the checks are compiled into `build/tests`, which `ctest --test-dir build` runs.
None of the **three shapes refers to the other two**, and the program never tests which kind it is holding. `make_shape` returns a `std::unique_ptr<shape>` and no later code inspects the object behind the pointer.
